# Editing content without code changes

Programmes (the 6 class cards) and workshops (Women in Islam, the Nikah
Series, past workshops, etc.) live as JSON files in `content/`, not in the
page components. They're editable two ways:

1. **Directly** — open the file in `content/` and edit it. Any Netlify
   deploy of `main` picks it up.
2. **Through a form at `/admin`** — no code, no editor. This needs a one-time
   setup (below), then works from a phone or any browser.

Everything else (the 6 programme detail pages under `src/pages/classes/`,
their "What's Included" lists, FAQ, testimonials, etc.) is still in code —
that was a deliberate scope decision, not a limitation. See "What's
editable" below.

## What's editable

| Content | Where | Editable via `/admin` |
|---|---|---|
| Programme cards (title, price, tag, description, image) | `content/settings/programmes.json` | Yes |
| Workshops — current and past, online and in-person | `content/workshops/*.json` | Yes — add, edit, delete |
| Programme detail pages (body copy, "What's Included", quotes) | `src/pages/classes/*.tsx` | No — code change + deploy |

A new workshop just needs a new entry in `/admin`. A new **programme**
(a 7th card) can be added the same way, but its "View Details" link won't
resolve until a developer builds the matching page under
`src/pages/classes/` — the field description in `/admin` notes this.

## One-time setup: Tina Cloud

The `/admin` form needs somewhere to authenticate the editor and push
commits back to GitHub. That's [Tina Cloud](https://app.tina.io) (the
company behind TinaCMS) — free for one project, one editor.

1. Sign up at app.tina.io and create a project connected to this GitHub repo
   (branch: `main`).
2. Tina Cloud gives you a **Client ID** and a **read/write Token**.
3. In Netlify: Site settings → Environment variables, add:
   - `TINA_CLIENT_ID` = the client ID
   - `TINA_TOKEN` = the token
4. Trigger a redeploy. The build now compiles the admin app too (see
   `netlify.toml` — it's conditional on `TINA_CLIENT_ID` being set, so the
   site deploys fine either way).
5. Visit `https://beginnersmadrasah.co.za/admin`, sign in with the account
   used for the Tina Cloud project, and start editing.

Every save in `/admin` becomes a git commit on `main` and triggers a normal
Netlify deploy — changes go live in about 1-2 minutes, same as any other
deploy.

## Local editing (no Tina Cloud needed)

```
pnpm --filter @workspace/bmc-website run dev:cms
```

(Needs `PORT` and `BASE_PATH=/` set, same as the plain `dev` script.) This
runs a local, account-free version of the same `/admin` form at
`http://localhost:5000/admin`, writing straight to the files in `content/`
on disk.

## Images

Uploads through `/admin` land in `public/assets/`, next to the existing
hand-optimised photos, and show up in the media picker there. For best
load times, convert photos to WebP before uploading (the rest of the site's
images are WebP, typically 40-90KB) — a raw phone photo can be several MB.

## Notes for whoever maintains this next

- Content is plain JSON, imported directly by `src/data/programmes.ts` and
  `src/data/workshops.ts` at build time via `import.meta.glob` — the site
  has zero runtime dependency on Tina. Tina Cloud is only in the picture
  when someone opens `/admin`; if it ever goes away, editing by hand still
  works exactly the same.
- `tina/config.ts` is the schema `/admin` is built from. If you add a field
  in the TypeScript interfaces (`src/data/programmes.ts`,
  `src/data/workshops.ts`), add the matching field in `tina/config.ts` too,
  or `/admin` won't expose it.
- `tina/__generated__/` and `public/admin/` are build output, gitignored,
  regenerated by `tinacms dev` / `tinacms build`. `tina/tina-lock.json` is
  the one generated file that *is* committed — it's how Tina detects schema
  drift.
